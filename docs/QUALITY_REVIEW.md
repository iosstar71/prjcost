## 3. 영역별 자세히

### 3-1. 화면 처리 (안정성 3.5)
- 값 하나를 고치면 탭 화면 HTML 을 통째로 다시 만들고 포커스를 되찾는 방식. 단순하고 빠르지만(최대 47ms), **키 · 포커스 · 입력기와 부딪히기 쉬움** — 이번 깜빡임, 예전의 Tab 포커스 잃음 · 빠른 키 누락이 같은 계열.
- 개선 방향: ① 값만 바뀐 경우(구조가 그대로)는 칸 · 합계만 바꾸고 전체를 다시 그리지 않기, ② 키 처리(`grid.js` · `app.js` · `ui.js` 세 곳)를 한 곳으로 모으기.

### 3-2. 구조 (3.0)
- `app.js` 670줄: 열기 · 저장 · 되돌리기 · 기준정보 · 마스터 · 버전 · 견적 · 양식 출력 · 부서 등 동작 약 40개가 한 객체(`A`)에. 기능별 파일(마스터 · 버전 · 견적 · 출력)로 나누면 고칠 곳을 찾기 쉬워짐.
- 기준정보의 **마스터 / 프로젝트 / 금액** 구분이 `PROJECT_ONLY` · `masterOf` 안의 코드로만 정해짐 → 새 항목을 더할 때 빠뜨리기 쉬움. 항목 정의 표(이름 · 범위: 마스터/프로젝트 · 금액 여부 · 화면 탭)를 한 곳에 두고 화면 · 마스터 파일 · 반영을 그 표에서 만들면 안전.
- 예전 자료 변환이 `Model.normalize` 한 함수에 누적(조건문 방식). 자료 판 번호(data_version)와 단계별 변환으로 바꾸면 어떤 파일이 어떤 변환을 거쳤는지 분명해짐.

### 3-3. 가독성 · 중복 (3.0 · 3.5)
- `views.js` 긴 줄 71개, `report.js` 18개 — 화면 · 보고서를 템플릿 글로 길게 이어 씀. 표 한 줄 · 칸 하나를 만드는 작은 함수로 나누면 검토가 쉬워짐.
- 중복: 날짜 표시(`dot` · `lastDay`: report · template), 줄 높이 계산(workbook · report), 분배 방식 이름(report · template), 결재자 직함(views · workbook · make_templates · template) → `util.js` / 상수 한 곳으로.

### 3-4. 시험 (4.0)
- 강점: 계산 회귀(42가지 저장 결과와 1원 단위 비교), v4 파일 호환, 저장 · 백업 · 충돌, 붙여넣기, 양식 채우기를 실제 브라우저로 시험.
- 약점: 화면 시험 47개가 한 흐름(457줄)이라 앞 항목이 깨지면 뒤가 줄줄이 실패, 키 입력 타이밍에 민감(헤드리스에서 가끔 키가 늦음). 시나리오별로 나누고 각자 준비 자료로 시작하게 하면 원인 찾기가 쉬움. 이번에 쓴 '입력 흔들기' 시험을 정식 시험으로 넣기 권장.
- 정적 검사 없음: ESLint(안 쓰는 변수 · 비교 실수), 자료형 검사(JSDoc + `checkJs`)를 계산 · 엑셀 쪽부터.

### 3-5. 엑셀 · 양식 (자료 안전 4.5, 양식 엔진 주의)
- 외부 라이브러리 없이 zip · XML 을 직접 다룸 — 배포가 간단한 대신 정규식으로 XML 을 읽음. 우리 파일 · openpyxl 파일 · Excel 이 다시 저장한 파일에서 확인했으나, Excel 의 표(ListObject) · 조건부 서식 · 공유 수식이 많은 양식에서는 반복 줄을 넣을 때 어긋날 수 있음 (문서에 한계 적음). **실제 회사 Excel 로 저장한 양식 파일**을 시험 자료로 넣어 두기 권장.
- 되돌리기는 변경마다 프로젝트 전체를 글로 저장(100번). 지금 크기(32KB)는 문제없지만, 프로젝트 안의 **버전 자료가 커지면** 함께 커짐 → 되돌리기 저장에서 버전 자료는 빼는 것이 좋음.

### 3-6. 환경 제약 (참고)
- 폴더 저장은 크롬 · 엣지만(File System Access). 다른 브라우저는 내려받기로만 저장.
- 혼자 쓰는 것을 전제 — 같은 파일을 두 사람이 동시에 고치면 나중 사람이 '바뀐 파일' 경고를 받는 정도의 보호.
